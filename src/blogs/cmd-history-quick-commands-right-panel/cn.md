# 命令历史与快捷命令可以停靠到右侧栏了

每个终端标签页的页脚都有两个高频按钮：**历史图标**（命令历史）和 **Q / 闪电图标**（快捷命令）。它们好用，恰恰因为一键可达；它们碍事，也恰恰因为同一个原因——弹出的浮层都会盖住你正在看的终端。

从 **v5.5.35** 起，这两个面板各有了**两个家**。默认它们还住在页脚，但任何一个都可以停靠进**右侧栏**——也就是已经放着 AI 对话和会话信息面板的那一列——并随时搬回来。

## 两个面板，两个家

| | 命令历史 | 快捷命令 |
| --- | --- | --- |
| 页脚（默认） | 历史图标上方的弹层 | 页脚上方的浮动框 |
| 右侧栏 | `cmdHistory` 标签页，标题栏是历史图标 | `quickCommands` 标签页，标题栏是闪电图标 |
| 内容一致吗 | 一致——同一个组件：搜索、按频率排序、清空、存为快捷命令、多终端运行都跟着走 | 一致——同一个组件：搜索、标签筛选、按频率排序都跟着走 |

实现上它真的就是同一个组件换了个地方渲染（`inline` 模式）：停靠版去掉触发器和弹层外壳，直接由右侧栏容器包裹面板本体，所以不存在第二套会跑偏的实现。

## 怎么搬

每个面板的头部都有一个移动图标，两个图标是镜像关系，坐在同一个位置：

- 在**页脚**时，图标是朝**右侧竖条**的箭头——点一下，面板停靠进右侧栏。
- **停靠后**，图标变成朝**底部横条**的箭头——点一下，面板交还给页脚。

搬家永远看得见，不会像凭空消失：

- 把命令历史送回页脚时，会**直接打开页脚弹层**。
- 把快捷命令送回页脚时，会**直接打开页脚浮动框**。

## 停靠时，页脚按钮会变成什么

停靠不会留下一个点不动的死按钮。当面板住在右侧栏时，它的页脚按钮就变成**面板开关**，和信息面板、AI 按钮完全相同的行为：

- 点页脚**历史图标** → 右侧栏打开到历史标签页；再点 → 关闭。标签页在前时按钮保持高亮。
- 点页脚 **Q 图标** → 右侧栏打开到快捷命令标签页；再点 → 关闭，同样有高亮状态。

用别的方式关掉右侧栏（它自己的关闭按钮、切到别的标签页），页脚按钮照样好使——再点一次就会把对应的标签页重新打开。

## 几个值得知道的细节

- **选择会被记住。** 每个面板住在哪是一个持久化偏好，重启之后页脚按钮依然落在你上次放的地方。
- **快捷命令的置顶不会丢。** 停靠时如果页脚框是置顶的，置顶状态会保留在 store 里，搬回来时原样恢复。停靠期间面板自己不再显示置顶/关闭按钮——右侧栏标题栏已经有了；布局也不再为置顶框预留那一截高度。
- **历史弹层不会残留。** 把历史面板停靠过去时，页脚的弹层会先关掉，不会留下一个指着空位置的孤儿弹层。
- **一列住四位。** 历史、快捷命令、AI 对话和会话信息现在都是右侧栏的标签页。把右侧栏钉住，它就变成停靠栏——终端被挤到一边，你的命令常驻在会话旁边，而不是浮在终端上面。

## 什么时候停靠，什么时候不

- **停靠**适合整天反复执行命令的场景：把右侧栏钉住，历史或快捷命令摆在宽终端旁边，比一天开关五十次弹层舒服得多。
- **留页脚**适合窗口很窄的时候：窄窗口下用完即走的浮层更省地方，关掉之后零成本。

反正改主意只需要点一下——这就是这个功能的全部意义。
