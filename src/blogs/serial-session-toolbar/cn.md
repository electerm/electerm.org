# electerm 串口会话新增工具栏

electerm 的串口标签页本质上就是一个连着设备的终端。大多数硬件调试做到这一步就够了——直到设备
回给你的不是文字而是字节，或者因为某根控制线状态不对而干脆不说话。以往的做法是在 electerm
旁边再开一个工具。

从 **electerm 5.11.8** 开始，串口标签页有了自己的会话工具栏。一个图标打开一个面板，里面包含
DTR、RTS 和 break 控制，CTS、DSR、DCD 状态指示，四种查看接收数据的方式，以及一个只写你输入
字节的原始发送框。

串口标签页本身并不新，新的是这个工具栏。如果你还没建立过串口会话，文末链接的短视频演示了如何
完成第一次连接。

## 1. 面板在哪里

打开一个串口书签，看终端上方的会话控制栏。桌面上会出现一个滑块图标，和其他会话图标排在一
起。鼠标悬停时提示文字是 *Serial: DTR / RTS / break, view of received data, send bytes*。点击
后面板会在终端旁边展开，设备输出依然可见。

手机上同样的滑块图标位于 **…** 菜单内，打开的是同一个面板，只是显示为标题为 **Serial** 的
对话框。两端的控件和顺序完全一致。

当会话不是默认的 ASCII 视图时——比如切到了 HEX、DEC、BIN，设置了帧字节，或者 break 脉冲正在
闪烁——滑块图标会变绿。扫一眼就知道当前状态不是默认值。

## 2. 控制线路，观察对端

面板第一行有三个按钮。DTR 和 RTS 是开关，break 是一次性动作。

| 控件 | 点击后发生什么 | 状态如何显示 |
| --- | --- | --- |
| DTR | 在线路有效与空闲之间切换 | 按钮为蓝色时表示线路有效 |
| RTS | 在线路有效与空闲之间切换 | 按钮为蓝色时表示线路有效 |
| Break | 把线路拉低约 250 毫秒，然后自动释放 | 闪电图标短暂闪烁 |

Break 被设计成脉冲而不是开关是有原因的：如果一直保持 break 状态，端口会一直收不到数据，直到
有人手动关掉它。所以面板不会把它显示成一个可以锁定的开关。

按钮下方是三个只读指示灯。绿色表示线路有效，空闲时保持普通文字颜色。鼠标悬停可以看到完整
名称和当前状态。

| 指示灯 | 全称 | 含义 |
| --- | --- | --- |
| CTS | Clear to send | 设备已准备好接收数据 |
| DSR | Data set ready | 设备在线并已就绪 |
| DCD | Carrier detect | 检测到载波 |

面板里没有 RI（振铃指示）灯。

DTR 和 RTS 在会话建立时默认为有效。面板在标签页处于活动状态时大约每 300 毫秒刷新一次指示
灯，切回应用窗口时也会立即读取一次。线路状态不会保存在书签里，所以每次新建会话都从同样的
默认状态开始。

一个注意点：如果书签启用了 RTS/CTS 硬件流控，RTS 由驱动程序掌控，你的修改可能被拒绝。这时
面板会显示一行红色错误，而不是悄悄什么都没做。

## 3. 按字节查看，而不是按字符

**Received data as** 是一排四个按钮——**ASCII HEX DEC BIN**。

| 视图 | 一个字节显示成什么 | 每行字节数 |
| --- | --- | --- |
| ASCII | 字符本身，并应用书签里的接收换行设置 | 由设备决定 |
| HEX | 两位大写十六进制数，例如 `4A` | 16 |
| DEC | 0 到 255 的十进制数，补齐三位 | 16 |
| BIN | 八位 0 和 1，例如 `01001010` | 8 |

ASCII 是默认视图，表现和一个普通终端一样。其他三种视图默认会在数值旁边附加一列 **ASCII
column**，可打印字符显示原字符，其余显示为 `.`。在 ASCII 视图下这个勾选项不可用，因为那一列
本来就是重复的。

还有两个选项对二进制协议很有用：

- **Frame start** 和 **Frame stop** 各接收一个十六进制字节，例如 `10` 或 `0xFF`。设置起始字节
  后，每个帧从这个字节开始换行；设置结束字节后，在该字节之后换行。已经收到的数据会按新的
  边界重新绘制，取消勾选时输入的值仍保留在框里。
- 在 HEX、DEC 和 BIN 视图中，**方向键会移动一个高亮的字节光标**，不会把按键发给设备。面板下方
  会显示该字节的偏移量、十六进制、十进制和二进制值，以及可打印时的对应字符。

切换视图会清屏并按当前格式重绘本次会话保留下来的数据，上限大约 256 KB，因此不需要重连就能
对比不同格式。之前的 ASCII 输出仍留在回滚区里，重绘的内容也不会再次写入会话日志。

## 4. 发送你输入的原始字节

面板底部有一个格式下拉框、一个输入框，以及 **Send** 按钮。按 Enter 也可以发送。输入框的示例
文字会随格式变化。

| 格式 | 可输入的示例 | 说明 |
| --- | --- | --- |
| HEX | `1B 41 0D`、`0x1B,0x41`、`1B410D` | 空格、逗号、分号都可以分隔字节；`0x` 可省略；连写的字符串会按两位一组拆开 |
| DEC | `27 65 13` | 0 到 255 的整数 |
| BIN | `00011011 01000001`、`0b00011011` | `0b` 可省略 |
| ASCII | `AT\r\n`、`\x1B` | 支持 `\r`、`\n`、`\t`、`\\` 和 `\xHH` 转义 |

输入不合法时，输入框下方会出现红色错误提示，并且不会发送任何数据——例如十六进制位数为奇数、
数值超出一个字节的范围，或者 ASCII 模式下出现需要多个字节表示的字符。

**原始发送就是完全原样。** 在串口标签页里正常打字，会加上书签设置的发送换行符，默认是 `\r`。
原始发送框什么都不加，所以设备需要换行符时，请自己写上 `0D` 或 `0A`。接收换行设置仍然有效，
但只在 ASCII 视图下生效。

## 5. 需要知道的限制

- 面板文案目前只有英文，串口控件还没有加入多语言翻译。
- DTR 和 RTS 每次连接时都设为有效，状态不会在会话之间保留。
- Break 总会在大约四分之一秒后自动释放。
- 启用 RTS/CTS 流控后，RTS 归流控驱动管理，可能无法修改。
- 只显示 CTS、DSR、DCD，不显示 RI。
- 在 HEX、DEC、BIN 视图里，方向键用于移动字节光标，不会转发给设备。
- 字节视图每次切换都会重绘屏幕。如果需要不受影响的记录，请保持终端日志开启；重绘本身不会
  写入日志。

## 6. 动手试试

1. 升级到 **electerm 5.11.8** 或更新版本。
2. 新建一个类型为 **serial** 的书签，选择设备路径，并按设备设置波特率、数据位、停止位和校验位。
   默认值是 `9600`、`8`、`1`、`none`。
3. 打开标签页，点击滑块图标，观察 **CTS**、**DSR** 和 **DCD**。
4. 切换一次 **DTR**，确认设备有反应。
5. 把 **Received data as** 设为 HEX，然后发送 `48 65 6C 6C 6F 0D`，也就是 `Hello` 加一个回车，
   再按字节读取设备的回复。
6. 如果设备用 `0x10` 作为帧边界，把 **Frame start** 设为 `10`，之后每个回复都会从新的一行开始。

有具体设备相关的问题或想报告缺陷，欢迎到
[electerm 问题反馈区](https://github.com/electerm/electerm/issues) 提出。
