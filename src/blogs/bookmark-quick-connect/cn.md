# Electerm 先存书签再连接：为什么 SSH/Telnet/VNC 都要书签，什么时候用快捷连接

新手最常见的困惑：在 electerm 里打开一个本地终端，手敲 `telnet 192.168.1.1` 或 `ssh user@server`，然后问为什么没有密码管理、没有 SFTP 面板、没有隧道、没有会话保活。答案是：**那根本不是一次 electerm 会话**——只是在本地 pty 里跑了一个 `telnet` / `ssh` 命令行程序。Electerm 看不到这条连接，它的所有功能自然都用不上。

规则很简单：

> **在 electerm 里，功能都长在书签上。先存书签，再连接。不存就没有功能——除非你用快捷连接。**

这篇讲清楚书签优先的模型、每种连接类型能解锁什么，以及不想存时的逃生通道。

## 1. 心智模型：书签 = 连接 + 它的全部功能

Electerm 里的每条连接都从**书签**开始：一条保存下来的记录，带 `type`（ssh、telnet、serial、vnc、rdp、spice、ftp、web、local）、地址、账号密码，以及这个会话的全部功能开关。

侧边栏 → **新建书签**，选类型，填主机/端口/账号，保存，双击连接。整个工作流就是这样。

不同类型挂的功能不一样：

| 类型 | 地址字段 | 挂在书签上的功能 |
|---|---|---|
| **ssh** | 主机、端口（22）、用户名、密码 / 密钥 / 证书 | ssh-agent、profiles、跳板（hopping）、proxy-command / NetBird、隧道（-L/-R/-D）、SFTP + 终端 SFTP 分栏、X11、快捷命令、触发器、保活、连上后脚本、批量输入 |
| **telnet** | 主机、端口（23）、用户名、密码、登录/密码提示符 | 字符集、快捷命令、触发器、连上后脚本、保活、批量输入 |
| **serial** | 设备路径、波特率（9600）、数据位 / 校验 / 流控 | 收发换行转换、优雅退出序列、触发器 |
| **vnc / rdp / spice** | 主机、端口、用户名、密码 | 只读/缩放/画质选项、共享模式 |
| **ftp** | 主机、端口（21）、用户名、密码、编码 | FTP 上的文件面板 |
| **web** | 网址 | 内嵌浏览器标签页，随会话集合同步 |
| **local** | 起始目录 | 带主题、触发器、快捷命令的本地 pty |

没有书签，这些东西就没地方存。这是刻意设计：书签才会被系统钥匙串加密、被 WebDAV / 云同步、被备份、被 `electerm://` 深度链接分享、被 AI / MCP 调用。

## 2. 经典误区：在本地终端里手敲 `telnet` / `ssh`

Electerm 自带好用的**本地终端**标签页（你本机的 node-pty）。很多人会顺手把它当普通终端模拟器用：

```bash
telnet 192.168.1.100
ssh root@192.168.1.100 -p 2222
```

能连上——命令行程序跑起来了——但 electerm 只看到一个不透明的本地 shell。具体丢掉的东西：

- 保存的账号密码、密码管理器自动填充、钥匙串加密
- SFTP / 文件面板、trzsz 传输集成、路径跟随终端
- 隧道、跳板、proxy-command、NetBird 自动探测
- 触发器、快捷命令、连上后自动脚本
- 保活、自动重连、工作区恢复
- 单主机的字符集（`encode` / `envLang`）、终端类型、代理字段
- 历史搜索、批量操作、服务器信息面板

凡是"在 electerm 里不行，在系统终端里手敲就行"的问题，先查第一件事：**你是真的建了对应类型的书签，还是只是在本地标签页里跑了个 CLI？** 十有八九是后者。

一句话：*本地标签页是给你操作本机的；连别的机器一律用书签标签页。*

## 3. 30 秒存一条书签

1. 侧边栏 → 书签 → **新建**（或 `+` → 书签标签页）。
2. 选 **type**：服务器选 `ssh`，交换机/老设备选 `telnet`，console 线选 `serial`，桌面选 `vnc` / `rdp`，纯传文件选 `ftp`。
3. 填**主机**、**端口**、**用户名**、**密码**（ssh 还可以填密钥/证书）。顺手起个**标题**，分个类、配个颜色。
4. 可选但值得：ssh 打开 **SFTP**，中文服务器设好**字符集**，加一条**快捷命令**，调好**保活**。
5. 保存 → 双击 → 连接。以后每次重连、同步、AI/MCP 看到的都是同一条书签。

Telnet 小贴士：老设备的提示符五花八门。自动登录卡住时，去书签的**登录提示符** / **密码提示符**正则里改成设备实际打印的样子（默认类似 `/login[: ]*$/i` 和 `/password[: ]*$/i`）。

Serial 小贴士：选好设备 **path**，设好**波特率**（默认 9600，115200 很常见），输出重叠或粘连就查收发换行设置。

## 4. 不想存？用快捷连接

有些主机真的只连一次——客户临时给的机器、看一眼就删的虚拟机。这时也别用本地 CLI 糊弄，用**快捷连接**：它会打开一个真正的 electerm 会话（正确的协议处理、正确的默认参数），只是不往数据库里写书签。

入口有三处：

- **`+`（新建标签页）菜单**——顶部输入行，闪电图标；
- **空状态页**——一个标签页都没打开时；
- **侧边栏闪电图标**——快捷连接弹窗。

输入连接字符串，回车，即连。不存书签（地址会像浏览器一样进**历史记录**）。

支持的格式（完整规范见 [Quick Connect wiki](https://github.com/electerm/electerm/wiki/quick-connect)）：

```text
user@host
user@host:22
192.168.1.100
192.168.1.100:2222
ssh://user:password@host:22
telnet://user:password@192.168.1.100:23
vnc://user@192.168.1.100:5900
rdp://admin@192.168.1.100:3389
serial:///dev/tty.usbserial?baudRate=115200
ftp://user:password@host:21
https://192.168.1.1:8443
electerm://user@host:22?type=ssh
electerm://192.168.1.100?type=telnet
```

进阶：在后面拼 `?title=核心交换机&opts={"term":"xterm-256color"}`，可以给这次会话 inline 指定额外书签字段。`electerm://` 链接同理，在 app 外面点一下就直接打开会话。

每种协议都有合理默认值（ssh 22、telnet 23、vnc/spice 5900、rdp 3389、ftp 21、serial 9600-8N1），所以短字符串开箱即用。

## 5. 书签 vs 快捷连接 vs 本地手敲，一张表看懂

| | 已存书签 | 快捷连接 | 本地标签页里手敲 `ssh` / `telnet` |
|---|---|---|---|
| 写入数据库 | 是 | 否（只进历史记录） | 否 |
| 真正的 electerm 会话 | 是 | 是 | **否**——pty 里跑 CLI 而已 |
| 账号 / 密钥 / 证书 | 保存、加密 | 每次 inline 现敲 | 每次手敲 |
| SFTP、隧道、跳板、代理 | 有 | 仅本次会话（不持久） | 无 |
| 触发器、快捷命令、脚本 | 存在书签上 | 只有默认值 | 无 |
| 同步 / 备份 / AI / 深度链接 | 有 | 无 | 无 |
| 适合 | 连两次以上的所有主机 | 真正的一次性主机 | 只做本机 shell 操作 |

## 速查

- 凡是在本地标签页里手敲 `telnet` / `ssh`，都是绕过 electerm。换成**对应类型的书签**。
- 书签类型决定处理器：`ssh` → 终端+SFTP+隧道，`telnet` → 带登录提示符的终端，`serial` → 串口，`vnc`/`rdp` → 桌面，`ftp`/`web` → 文件/浏览器。
- 只连一次、永不再见的主机？**快捷连接**（`user@host`、`telnet://…`、`electerm://…?type=…`）——真会话，不落盘。
- 连两次就存下来。书签才会被加密、同步、备份和自动化。
